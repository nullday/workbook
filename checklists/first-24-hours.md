## 🔴 ФАЗА 1 — СДЕРЖИВАНИЕ (первые 30 минут)

Цель: не дать вирусу распространиться дальше.

- [ ] **Немедленно сообщить руководству** о факте атаки
- [ ] **Отключить заражённые компьютеры от сети** — физически отсоединить кабель Ethernet, отключить Wi-Fi
  > ⚠️ Не выключайте компьютеры — это может уничтожить данные в оперативной памяти, важные для анализа
- [ ] **Отключить VPN-подключения** всех удалённых сотрудников
- [ ] **Отключить сетевые шары** (временно остановить File Server / SMB) на серверах, к которым был доступ
- [ ] **Уведомить сотрудников** — не включать компьютеры, не подключаться к корпоративной сети
- [ ] **Зафиксировать время и симптомы** — скриншоты, фото экранов с требованием выкупа
- [ ] **Сохранить записку вымогателей** — файл README.txt / DECRYPT.txt и т.п. (может помочь в идентификации штамма)

---

## 🟠 ФАЗА 2 — ОЦЕНКА УЩЕРБА (первые 2 часа)

Цель: понять масштаб и что уцелело.

### Инвентаризация заражённых узлов

- [ ] Составить список всех заражённых компьютеров и серверов
- [ ] Определить, какие серверы **не затронуты** (изолированные сегменты, резервные серверы)
- [ ] Проверить состояние **контроллера домена** — это приоритет №1
- [ ] Проверить состояние **сервера резервного копирования**

### Оценка резервных копий

- [ ] Найти все носители с резервными копиями (NAS, лента, облако, внешние диски)
- [ ] Проверить дату последней успешной резервной копии каждой системы
- [ ] Убедиться, что носители с бэкапами **физически отключены от заражённой сети**
- [ ] Проверить, не зашифрованы ли сами резервные копии

> Подробный аудит бэкапов — в [backup-audit.md](backup-audit.md)

### Идентификация штамма

- [ ] Определить расширение зашифрованных файлов (`.locked`, `.encrypted`, `.STOP` и т.д.)
- [ ] Проверить штамм на [ID Ransomware](https://id-ransomware.malwarehunterteam.com/) — загрузить записку вымогателей
- [ ] Проверить наличие публичного дешифратора на [No More Ransom](https://www.nomoreransom.org/ru/)

---

## 🟡 ФАЗА 3 — ПЕРВИЧНЫЙ АНАЛИЗ (2–8 часов)

Цель: найти точку входа, чтобы не повторить ситуацию.

### Возможные векторы атаки

- [ ] Проверить журналы RDP-подключений — были ли успешные входы с внешних IP
  ```
  Event ID 4624 (успешный вход) + Logon Type 10 (RemoteInteractive)
  ```
- [ ] Проверить журналы VPN — подозрительные подключения в нерабочее время
- [ ] Проверить почтовые журналы — фишинговые письма с вложениями или ссылками
- [ ] Проверить браузерную историю на заражённых машинах
- [ ] Проверить журналы файрвола — исходящие соединения на нестандартные порты
- [ ] Найти «нулевой пациент» — первую заражённую машину по времени изменения файлов

### Документирование

- [ ] Записать все находки с временными метками
- [ ] Сохранить копии журналов с заражённых систем (экспорт Event Log)
- [ ] Сфотографировать физические серверы и их индикаторы

---

## 🟢 ФАЗА 4 — ПОДГОТОВКА К ВОССТАНОВЛЕНИЮ (8–24 часа)

Цель: создать условия для чистого старта.

### Планирование

- [ ] Определить **приоритетный порядок восстановления** систем:
  1. Сетевая инфраструктура (маршрутизатор, коммутаторы)
  2. DNS и Active Directory
  3. Файловый сервер
  4. Бизнес-приложения (1С, CRM, ERP)
  5. Почта и коммуникации
  6. Рабочие места сотрудников
  7. Периферия (СКУД, телефония, видеонаблюдение)

- [ ] Оценить наличие **чистого оборудования** для разворачивания
- [ ] Подготовить дистрибутивы ОС (Windows Server, Windows 10/11)
- [ ] Подготовить лицензионные ключи
- [ ] Подготовить установочные файлы корпоративного ПО (1С, антивирус, офисный пакет)

### Коммуникация

- [ ] Уведомить ключевых сотрудников о примерных сроках восстановления
- [ ] Организовать временный канал связи (личные телефоны, мессенджеры)
- [ ] При необходимости — уведомить контрагентов и клиентов о временной недоступности
- [ ] Решить вопрос о необходимости обращения в правоохранительные органы

### Юридические вопросы

- [ ] Составить [Акт об инциденте](../templates/incident-report.md)
- [ ] Оценить необходимость уведомления Роскомнадзора (если обрабатывались персональные данные — 72 часа по 152-ФЗ)
- [ ] Уведомить страховую компанию (если есть киберстрахование)

## ⛔ Чего категорически НЕ делать

| Действие | Почему нельзя |
|---|---|
| Платить выкуп | Не гарантирует получение ключа, финансирует преступников |
| Запускать антивирус на заражённой системе «для лечения» | Не удалит всех компонентов, создаст иллюзию безопасности |
| Включать заражённые машины обратно в сеть | Мгновенно распространит заражение дальше |
| Форматировать диски немедленно | Уничтожит криминалистические данные, может понадобиться для анализа |
| Пытаться вручную переименовать зашифрованные файлы | Не поможет, только потеря времени |
| Скрывать факт атаки от руководства | Затянет принятие решений и увеличит ущерб |
