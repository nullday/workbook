# 🖥️ Playbook: Восстановление хоста виртуализации Hyper-V

**Типовое время:** 3–6 часов (хост) + время восстановления каждой ВМ  
**Сложность:** ⭐⭐⭐ Высокая  
**Требования:** дистрибутив Windows Server, доступ к бэкапам ВМ, документация по vSwitch и сети

> Шифровальщик, получивший доступ к хосту Hyper-V, шифрует VHDX-файлы — и одним ударом выводит из строя все виртуальные машины: контроллер домена, 1С, файловый сервер. Восстановление хоста — первый шаг перед восстановлением гостевых систем, поэтому этот playbook выполняется **до** playbook'ов AD и 1С, если они виртуализированы.

---

## Шаг 0. Оцените, что именно пострадало

Сценарии различаются принципиально:

| Сценарий | Признак | Действия |
|---|---|---|
| **A. Зашифрованы гостевые ОС изнутри** | Хост работает, VHDX цел, шифрование внутри ВМ | Хост можно не переустанавливать после проверки; восстанавливать отдельные ВМ |
| **B. Зашифрован хост (VHDX-файлы)** | Файлы `.vhdx` переименованы/нечитаемы, ВМ не запускаются | Полная переустановка хоста + восстановление всех ВМ из бэкапов |
| **C. Зашифровано и то и другое** | Атакующий имел админ-доступ к хосту | Как сценарий B, плюс обязательная смена всех учётных данных до запуска |

- [ ] Определить сценарий: `A / B / C`
- [ ] **Сохранить конфигурацию до переустановки** (если хост ещё загружается, с изолированной консоли):

```powershell
# Инвентаризация ВМ — сохранить вывод на чистый носитель
Get-VM | Select-Object Name, Generation, ProcessorCount, MemoryStartup, State |
    Export-Csv D:\rescue\vm-inventory.csv -NoTypeInformation

# Сетевые адаптеры и MAC-адреса (критично: лицензии 1С и другого ПО
# могут быть привязаны к MAC)
Get-VMNetworkAdapter -VMName * |
    Select-Object VMName, SwitchName, MacAddress, @{n='IP';e={$_.IPAddresses -join ','}} |
    Export-Csv D:\rescue\vm-network.csv -NoTypeInformation

# Виртуальные коммутаторы
Get-VMSwitch | Select-Object Name, SwitchType, NetAdapterInterfaceDescription |
    Export-Csv D:\rescue\vswitches.csv -NoTypeInformation
```

- [ ] Если конфигурация недоступна — восстановить её из [инвентаризации активов](../../templates/recovery-plan.md) или по памяти, письменно, до начала работ

## Шаг 1. Чистая установка хоста

- [ ] Установить Windows Server на **заново отформатированный** системный диск
- [ ] Диски с зашифрованными VHDX **не форматировать** до снятия копии (см. [Проверку возможности расшифровки](../../checklists/decryptor-check.md))
- [ ] Установить роль Hyper-V:

```powershell
Install-WindowsFeature -Name Hyper-V -IncludeManagementTools -Restart
```

- [ ] Задать новый, уникальный пароль локального администратора (не совпадающий со старым и с другими серверами)
- [ ] **Не вводить хост в домен**, если контроллер домена — виртуальная машина на этом же хосте. Сначала восстанавливается и запускается ВМ с DC, и только потом решается вопрос членства хоста в домене (для малых инфраструктур хост часто осознанно оставляют в рабочей группе — это уменьшает поверхность атаки на виртуализацию через домен)

## Шаг 2. Воссоздание виртуальных коммутаторов

Имена vSwitch должны совпадать со старыми — иначе при импорте ВМ сетевые адаптеры отвяжутся:

```powershell
# External-коммутатор (по данным из vswitches.csv)
New-VMSwitch -Name "External" -NetAdapterName "Ethernet" -AllowManagementOS $true

# Internal/Private — при наличии
New-VMSwitch -Name "Internal" -SwitchType Internal
```

- [ ] Все коммутаторы из старой конфигурации созданы с теми же именами
- [ ] VLAN-настройки адаптеров задокументированы и готовы к применению

## Шаг 3. Восстановление виртуальных машин

Порядок восстановления ВМ = общий порядок восстановления инфраструктуры:
`DC/DNS → файловый сервер → 1С/SQL → почта → остальные`

### Вариант 1. Бэкап средствами ПО резервного копирования (Veeam и аналоги)

- [ ] Установить консоль ПО резервного копирования на чистую машину
- [ ] Импортировать бэкап-репозиторий (носитель подключать только к чистой системе)
- [ ] Выполнить Instant Recovery / Full VM Restore по приоритетному списку
- [ ] Проверить, что восстановлена точка **до** заражения — дата шифрования известна из [аудита бэкапов](../../checklists/backup-audit.md)

### Вариант 2. Импорт из экспорта Hyper-V

```powershell
# Копирующий импорт с генерацией нового ID
Import-VM -Path "E:\Backups\SRV-DC01\Virtual Machines\<GUID>.vmcx" `
    -Copy -GenerateNewId `
    -VirtualMachinePath "D:\Hyper-V" -VhdDestinationPath "D:\Hyper-V\VHD"
```

### Вариант 3. Есть только VHDX-файлы (без конфигурации ВМ)

Создать новую ВМ и подключить восстановленный диск:

```powershell
New-VM -Name "SRV-DC01" -Generation 2 -MemoryStartupBytes 8GB `
    -VHDPath "D:\Hyper-V\VHD\SRV-DC01.vhdx" -SwitchName "External"
Set-VM -Name "SRV-DC01" -ProcessorCount 4
```

> ⚠️ **Поколение ВМ должно совпадать с исходным.** Gen 1 — BIOS-загрузка, Gen 2 — UEFI. VHDX от Gen 2-машины не загрузится в Gen 1-ВМ и наоборот. Если поколение неизвестно: серверные ОС от Windows Server 2012 R2 и новее чаще разворачивали на Gen 2, но проверяйте по факту загрузки.

### Привязка MAC-адресов

- [ ] Для ВМ с ПО, лицензируемым по MAC (лицензии 1С, СКУД, телефония), задать **старый статический MAC** из vm-network.csv:

```powershell
Set-VMNetworkAdapter -VMName "SRV-1C" -StaticMacAddress "00155D0A1B02"
```

## Шаг 4. Проверка каждой восстановленной ВМ

Перед подключением ВМ к продуктивной сети:

- [ ] ВМ запускается, гостевая ОС загружается без ошибок
- [ ] Службы интеграции работают: `Get-VMIntegrationService -VMName <имя>` — все критичные в состоянии OK
- [ ] Время в гостевой ОС корректно (для DC — проверить иерархию времени: PDC-эмулятор синхронизируется с внешним источником, остальные — с доменом)
- [ ] Сетевой адаптер подключён к правильному vSwitch, IP-адресация соответствует плану
- [ ] Внутри гостевой ОС выполнены проверки соответствующего playbook'а ([AD](../active-directory/README.md), [1С](../1c-server/README.md), [файловый сервер](../file-server/README.md))

## Шаг 5. Защита хоста до ввода в эксплуатацию

Хост виртуализации — самая ценная цель в сети: доступ к нему равен доступу ко всем серверам сразу.

- [ ] Управление хостом доступно только из выделенной админ-сети/VLAN, не из пользовательского сегмента
- [ ] RDP к хосту — только изнутри, с ограничением по IP
- [ ] Учётные записи для управления хостом отделены от повседневных админ-учёток домена
- [ ] Настроен бэкап ВМ на **изолированное** хранилище (учётная запись бэкап-сервера не имеет прав в домене и наоборот)
- [ ] Включён аудит входов на хост, настроено оповещение о входах в нерабочее время

> **Чекпоинты (снапшоты) — не резервные копии.** Они хранятся рядом с VHDX на том же хранилище и шифруются вместе с ним. Не учитывайте чекпоинты при планировании защиты данных.

---

## Критерии успешного завершения

- [ ] Хост переустановлен начисто, роль Hyper-V работает
- [ ] Все критичные ВМ восстановлены из точек **до** заражения и запускаются
- [ ] MAC-адреса лицензионно-зависимых ВМ сохранены, ПО активно
- [ ] Управление хостом изолировано от пользовательской сети
- [ ] Первый бэкап восстановленных ВМ создан и проверен тестовым восстановлением
