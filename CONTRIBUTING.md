# 🤝 Вклад в репозиторий

Спасибо, что готовы дополнить Ransomware Recovery Kit. Материалы используются людьми в момент реального инцидента — точность и проверяемость важнее скорости.

## Прежде чем начать

1. Проверьте [открытые Issues](../../issues) — возможно, ваш вопрос уже обсуждается.
2. Для мелких правок (опечатка, битая ссылка, неточная формулировка) — сразу открывайте Pull Request.
3. Для содержательных изменений (новый playbook, новый шаг в чеклисте, спорная рекомендация) — сначала откройте Issue и опишите предложение, чтобы не проделать работу впустую.

## Что особенно приветствуется

- Специфика конфигураций российского корпоративного ПО (1С, MikroTik, отечественные СУБД, средства защиты)
- Playbook'и для систем, которых пока нет в репозитории (см. [шаблон запроса нового playbook](.github/ISSUE_TEMPLATE/new-playbook.md))
- Актуализация ссылок на внешние сервисы (ID Ransomware, No More Ransom и аналоги) и нормативные сроки
- Реальный опыт восстановления — обезличенный, без данных конкретной компании

## Требования к содержанию

- **Проверяемость.** Команды PowerShell/консоли должны быть рабочими и протестированными хотя бы в лабораторной среде. Не публикуйте команды «на веру».
- **Без данных инцидентов.** Не включайте реальные IP, имена серверов, домены, ФИО, скриншоты живых систем.
- **Ссылки только на официальные источники.** Для дешифраторов, инструментов и юридических требований — ссылки на сайты вендоров/регуляторов, не на посредников.
- **Формулировки решений, а не мнений.** Если рекомендация спорная (например, про оплату выкупа) — излагайте факты и оставляйте решение читателю, без давления в ту или иную сторону.
- **Стиль.** Русский язык, оформление Markdown в духе уже существующих файлов: чеклисты через `- [ ]`, таблицы для сравнений, `⚠️`/`🔴` для акцентов — используйте умеренно, не в каждом абзаце.

## Как оформить Pull Request

1. Форкните репозиторий, создайте ветку с понятным именем (`fix/backup-audit-typo`, `feat/veeam-playbook`).
2. Внесите изменения одним логическим блоком на PR — не смешивайте правку опечатки и новый playbook в одном PR.
3. В описании PR укажите: что изменено и почему, откуда взята информация (документация вендора, личный опыт, нормативный акт).
4. Если меняете структуру (новая папка, новый файл) — обновите дерево в `README.md` и таблицу соответствующего раздела.
5. Дождитесь ревью — для playbook'ов и любых команд, выполняемых на продуктивных системах, проверка обязательна.

## Что не подойдёт

- Реклама сторонних коммерческих услуг восстановления (кроме контактов, уже указанных в README)
- Непроверенные «народные методы» без указания источника
- Материалы, нарушающие лицензию CC BY 4.0 (заимствования без права распространения)

## Лицензия вклада

Отправляя Pull Request, вы соглашаетесь, что ваш вклад распространяется на условиях [CC BY 4.0](LICENSE) — как и весь остальной репозиторий.

## Вопросы

Если не уверены, подходит ли материал — откройте Issue с вопросом или напишите sos@nullday.ru.
